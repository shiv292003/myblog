The first version of a project is often an argument with yourself about what to leave out.

This sample note takes the side of leaving out a little more.

## The useful minimum

Small doesn't have to mean unfinished. A chair with four sound legs is complete even without a cup holder.

For a website, the equivalent might be readable text, working links, and a reliable way to publish. Those are not the exciting parts of a feature list. They are the parts you use every day.

## A little code, when you need it

Technical writing has a place here too. Code is highlighted during the build, so readers don't need to download a library to see it:

```js
function keepWhatMatters(ideas) {
  return ideas.filter((idea) => idea.hasPurpose);
}
```

The test isn't whether another feature would be interesting to build. It's whether the thing you already have becomes better with it.
